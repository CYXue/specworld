# 对比页信息设计

> **产品侧已确认（2026-10-02）**：
> 1. 差异高亮走 **「克制」档**——默认只给 Δ 列，差值达到阈值 2 倍才上品牌色底 + 「更轻/更薄」标签；
> 2. **像素立绘：不做**。初版曾实现数据驱动 SVG（`scripts/sprite/`，几何由屏幕对角线/厚度/后摄数算出），但产品侧判定「效果不佳」，已从对比页与站点全部移除；生成器代码与 60 张 SVG 保留在仓库里不接页面，若将来要重启再重做视觉。
> 3. 其余各节（分组、主表/折叠划分、不可比清单、默认交互）按本文档执行。

> 这台页面要回答的唯一问题：**「这两台到底差在哪，差多少，哪些根本没法比。」**
> 它不是规格表的搬运，而是一份**带判断的差异报告**。判断依据全部来自字段与口径，不来自任何 LLM。

---

## 一、三条决定了整页长相的约束

1. **两家的数据是不对称的**。苹果不公布电池 mAh、RAM、有线充电功率；华为不公布蜂窝频段。所以「一侧有值、一侧官方未公布」是常态而不是异常，界面必须为它设计，而不是让它看起来像加载失败。
2. **有些参数天生不可比**。厂商标称续航（苹果「视频播放 34 小时」vs 华为同名字段的测试条件不同）、充电功率（峰值 vs 持续）——**这类只并列、不判定胜负**。
3. **不做「综合胜出」**。重量轻不等于更好（有人要大电池），价格高不等于更强（本站没有跑分）。**任何加权总分都是编造**，所以不设总分、不设推荐、不设「谁赢了」。

## 二、页面结构（从上到下）

```
┌─ ① 身份区 ────────────────────────────────┐
│  [像素立绘A]    型号A  vs  型号B    [像素立绘B] │
│  品牌 · 上市 · 起售价                        │
├─ ② 结论摘要（自动生成，带依据）──────────────┤
│  · A 屏幕大 0.3 英寸（6.9 vs 6.6，同口径）    │
│  · B 轻 22 克（199g vs 221g）                │
│  · 电池只有 B 公布，A 官方不公布 → 无法比较    │
├─ ③ 对比主表（7 组，约 26 行，一屏半看完）─────┤
│  分组标题 + 参数行（A 值 | 参数名 | B 值 | Δ）  │
├─ ④ 不可比清单 ────────────────────────────┤
│  只并列、不判定：厂商标称续航、充电口径 …      │
├─ ⑤ 折叠：完整规格 ────────────────────────┤
│  感应器 / 音频 / 定位 / 包装 / 频段 …         │
├─ ⑥ 折叠：官网原文规格（逐字段可溯源）─────────┤
└─ ⑦ 数据来源与口径说明 ─────────────────────┘
```

## 三、主表：哪些参数上桌

**入选标准（三条全满足才上主表）**：
① 两家覆盖率 ≥ 80%；② 口径一致、可逐项比较；③ 影响购买决策。
不满足的进「不可比清单」或「折叠区」，绝不硬塞进主表凑数。

### 分组与行（共 7 组 26 行）

| 组 | 行 | 比较方向 | 有意义差异阈值 |
|---|---|---|---|
| **A 一眼定位** | 上市时间 | 新者为新 | 任意 |
| | 起售价 | 低者便宜 | ≥ 300 元 |
| | 在售状态 | 中性 | — |
| | 一句话定位（自动生成） | 中性 | — |

| | 厚度 | 薄者优 | ≥ 0.3 mm |
| | 重量 | 轻者优 | ≥ 10 g |
| | 防尘抗水 | 中性 | — |
| | 配色数 | 中性 | — |
| **C 屏幕** | 尺寸 | 大者为大 | ≥ 0.2 英寸 |
| | 面板类型 | 中性 | — |
| | 分辨率 | 中性（看 ppi） | — |
| | ppi | 高者细腻 | ≥ 20 |

| | 峰值亮度（带口径角标） | 高者亮 | ≥ 200 nits |

## 四、折叠区：哪些不上主表

| 折叠组 | 内容 | 为什么折叠 |
|---|---|---|
| **完整规格** | 感应器、音频、定位、包装清单、环保、无障碍、系统需求 | 长尾信息，命中率低但有人查 |
| **网络细节** | 频段列表、SIM 卡型、星闪 | 只有一家公布，且极长 |
| **官网原文规格** | 官网 35/44 段原文逐条列出（可展开） | **这是本站可核查性的证据**：任何一个数字都能点回官网原文 |
| **数据来源与口径** | 每个字段的 source + URL + 采集时间 | 信任来自可追溯 |

## 五、差异高亮：四档，且必须克制

**核心规则：高亮的是「有意义的差异」，不是「所有不同的数字」。**
`8.75mm` vs `8.2mm` 差 0.55mm —— 高亮；`199g` vs `201g` 差 2g —— 不标，标了就是噪音。

| 档位 | 触发条件 | 视觉表现 |
|---|---|---|
| **不标** | 差值 < 有意义阈值 | 纯文本，只有 Δ 列不显示 |
| **弱高亮** | 差值 ≥ 阈值，且 < 阈值 × 2 | Δ 列显示差值 + 方向箭头，值加粗 |
| **强高亮** | 差值 ≥ 阈值 × 2 | 优势侧值加品牌色底 + 「更轻 / 更薄 / 更亮」标签 |
| **未公布** | 一侧为 `null` | 灰显文字「官方未公布」，**永不判定胜负**，行尾带口径说明入口 |
| **不可比** | 口径不同（标称续航等） | 整行斜纹底，只并列，不给 Δ |

**具体阈值**（写进代码，可调）：

```
重量 10g | 厚度 0.3mm | 屏幕 0.2in | ppi 20 | 刷新率 30Hz
峰值亮度 200nits | 电池 300mAh | 有线充 10W | 无线充 5W | 价格 300 元
```

**双重编码（无障碍要求）**：方向用 ▲▼ 形状 + 颜色同时表达，不依赖红绿；色盲模式下形状仍可读。
**不给「总分」「综合胜出」**：理由见第一节第 3 条。

## 六、Δ 列：本页最有用的一个东西

主表右侧固定一个窄列，只做一件事：**显示有意义的差值**。

```
重量      199 g   Δ 22 g ↓       221 g
厚度      8.75 mm Δ 0.55 mm ↓    8.2 mm
电池容量  官方未公布  ┄  5600 mAh（典型值）
```

- 差值永远以「更优一侧」为参照，箭头指向优势方；
- 未公布/不可比显示 `┄`，**不显示 0，也不显示「—」**（0 和 — 会被读成「差」和「没有」，而事实是「官方没说」）；
- 每行的口径说明（典型值/峰值/标称）作为角标，悬浮或点开显示原文出处。

## 七、两个断点

| 断点 | 布局 |
|---|---|
| 宽屏 ≥ 1024px | 三列网格：`A 值 | 参数名（居中固定列）| B 值`，Δ 挤在参数名下方小字 |
| 窄屏 < 1024px | 每个参数一张卡：参数名在上，A/B 两值左右并排，Δ 在右下角 |

**排版纪律（沿用参考项目踩过的结论）**：中文一律系统无衬线体、最小 12px；数字与型号名用等宽像素字（对齐好看且能强化「仪器读数」的观感）；像素字体**不用**于中文正文。

## 八、默认状态与交互

| 交互 | 默认 | 理由 |
|---|---|---|
| 「只看有意义的差异」开关 | **默认关** | 默认关能先建立完整印象；打开后是精读模式 |
| 折叠区 | 全部收起 | 首屏只给结论与主表 |
| 未公布项 | **不隐藏** | 隐藏会让人误以为两边一样 |
| 空状态 | 选不满两台时给「热门对阵」推荐 | 例如同价位、同代、折叠 vs 直板 |

## 九、还没解决的前置依赖（影响本页成立）

1. **苹果价格缺失**：苹果官网规格页不给价格，对比页最核心的「起售价」行现在是空的。对比页的 `autopricing.built.js` 与 `{IPHONE18PROMAX}$price.display.smart 起` 占位符说明**官网有定价接口**，需要单独探针打通。
2. **峰值亮度的口径**：两家都可能在文案里同时出现「典型」与「峰值」，若解析时串行会直接产出错误的高亮（已在闸门里加了「峰值 < 典型即拦截」）。
3. **华为例外值**：`mate90-pro-max` 的重量把「标准版 234g / 典藏版 235g」写在同一格，需要拆版本或取主版本并标注口径。

# 手机参数世界（暂定名）

把手机参数做成一个**一眼看懂、可核查、不编造**的静态站点。首版范围：

| 项 | 决定 |
|---|---|
| 品类 | **只做手机**（先把一条链路跑通，再考虑平板/手表/耳机） |
| 品牌 | **华为 + 苹果** |
| 机型 | **近 3 年在售**（含已停售但属该窗口的机型，用状态区分） |
| 形态 | 纯静态站（零后端），可另发一份到 B 站 Toy |
| 数据 | 厂商官网规格页为主源，第三方公开榜单为成绩源，缺数据一律 `null` |

## 为什么是这个形态

参考项目「AI 大模型世界」已经验证过的三件事，这里照搬：

1. **静态快照 + git 历史**：数据变更频率低（手机一年几场发布会），快照 + 版本历史足够，前端零密钥、零运行时依赖。
2. **档位用分位、不用绝对阈值**：屏幕大小/重量/价格/性能全部取「当前在售池」的分位，三年后不会悄悄失效。
3. **文案由数据套模板生成，不调用 LLM**：「这个价位里屏幕最亮的手机」必须可复现、可追溯到数据。

## 目录

```
docs/DATA-CONTRACT.md   数据契约（唯一字段定义源，先读这份）
docs/COMPARE-DESIGN.md  对比页信息设计定稿（主表/折叠/高亮阈值）
docs/PROBE-FINDINGS.md  官网取数通道探针（华为/苹果可解析性证据）
src/lib/types.ts        契约的 TypeScript 定义
src/lib/compare-spec.mjs 对比页行定义与差异等级（全站唯一判断源）
scripts/                取数、解析、校验、构建、立绘、站点、发布
data/products.json      唯一数据契约产物（提交入库）
data/sprites/           数据驱动的像素立绘（60 张 SVG）
```

## 管线

```
官方取数（scripts/sources）   华为规格页 50 台 / 苹果规格页 7 台 / 苹果对比页 42 列 / 苹果价格 7 台
        ↓
规范化（scripts/normalize）  官网字段 → 契约字段，口径判定 + 逐字段 provenance
        ↓
发布日期取证（_work/release-dates.json） 61 条，100% 日精度
        ↓
整合（scripts/sync）        窗口过滤 + 发布日期回填 + 校验闸门 + 原子写
        ↓
data/products.json          60 台（华为 47 / 苹果 13）+ _work/derived.json（分位/头衔/一句话定位）
        ↓
立绘（scripts/sprite）      60 张 SVG，几何全由数据算出
        ↓
对比页渲染器（scripts/preview）  自包含单文件 + 5 条自证断言
        ↓
站点骨架（scripts/site）    首页/列表/卡页/对比页，零外链
        ↓
发布封装（scripts/publish）  相对路径 + <base> 注入 + 指纹 + 发布清单
```

## 数据侧的两个结构性缺口（不是 bug，是官网决定的）

1. **苹果不公布电池 mAh、RAM、有线充电 W** —— 这些字段在苹果侧全部为 `null`，界面显示「官方未公布」，不做跨品牌比较。
2. **华为 20 台机型没有处理器章节** —— 这些机型 `chipset.name = null`，不从型号名猜芯片。

这两类 `null` 是**官网真没有**，不是解析漏。规范化的 null 计数表里逐台列出了这些机型。
